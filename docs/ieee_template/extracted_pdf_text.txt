Abstract—Users routinely work across a personal mix of
laptops, phones, and desktop computers, expecting them to share
clipboards, stream files, and forward inputs over a local network.
Yet establishing secure mutual trust across these devices on a
home or office LAN remains an unsolved operational problem.
Current ecosystems force an uncomfortable compromise: commercial tools (such as Apple Continuity and Google Quick Share)
rely on cloud identity servers that leak metadata and fail when
offline, while decentralized tools (such as KDE Connect) enforce
pairwise Trust-on-First-Use (TOFU) that requires O(N 2 ) manual
pairing operations. This paper presents Transitive Trust-on-FirstUse (T-TOFU), a zero-coordinator trust framework designed for
personal device meshes. Under T-TOFU, a user performs an
out-of-band verification ceremony on a single gateway device,
which automatically enrolls the newcomer across the entire mesh.
We introduce a canonical pool digest (PoolHash) computed over
sorted device fingerprints, coupled with anti-entropy heartbeat
gossip, to keep the trust state synchronized across dynamic LAN
nodes without an online certificate authority. We also detail
a flooded revocation mechanism that deterministically purges
de-authorized nodes. We built and evaluated T-TOFU within
Link, an open-source cross-platform runtime for Windows and
Android. Our measurements show that T-TOFU reduces human
pairing complexity to O(1) marginal effort per device while
achieving sub-100ms pool convergence with under 0.05 KB/s of
background network overhead.
Index Terms—Transitive Trust, Trust-on-First-Use, Usable
Security, Decentralized Device Mesh, Canonical Hash Gossip,
Mutual TLS, Personal Area Networks.

I. I NTRODUCTION
Most people now carry a smartphone alongside one or more
desktop and laptop computers [1]. Naturally, users want these

devices to talk to each other: copying text on a phone and
pasting it on a PC, mounting phone storage as a native drive
letter, forwarding touch gestures, or streaming audio across the
room. Doing this over a local Wi-Fi network without thirdparty servers ought to be straightforward, but securing such a
mesh without frustrating the user is notoriously difficult [2].
Any system attempting to bridge personal devices on a
Local Area Network (LAN) runs directly into what we term
the Usable-Security Trilemma (Fig. 1):
1) Local-First Independence: All communication, key
exchange, and state synchronization must stay strictly on
the local network, with zero reliance on cloud accounts
or external identity servers.
2) Cryptographic Rigor: The system must guarantee mutual authentication and data confidentiality over TLS
1.3, remaining resilient against active on-path attackers,
rogue APs, and ARP spoofing.
3) Minimal Human Friction: The manual effort needed
to enroll and manage devices must remain small and
constant as the user adds more hardware.
A. Shortcomings of Current Approaches
Commercial device-sync ecosystems, such as Apple Continuity/AirDrop, Google Quick Share, and Microsoft Phone
Link, bypass the usability barrier by tying all endpoints to
a corporate account (Apple ID or Google Account). While
setup is easy, this model forces devices to contact remote
WAN infrastructure, leaks user identity metadata over wireless

On the other hand, decentralized tools like KDE Connect [5] and Bluetooth Personal Area Networks [6] avoid
cloud dependencies by pairing devices directly with selfsigned certificates. The downside is steep: pairing is strictly

B. Our Contributions
We address this problem with Transitive Trust-on-FirstUse (T-TOFU), an open, coordinator-free trust architecture
for personal device networks. Specifically, this paper delivers:
A Transitive Trust Protocol: A mechanism allowing a
single human-verified pairing between an incoming node
and any active pool member to safely propagate mutual
authenticated trust to every other device in the mesh.
• A Canonical Pool Digest Algorithm: A lightweight
hashing technique (PoolHash) that lets nodes detect state
drift during routine heartbeats and reconcile trust tables
via anti-entropy gossip without a central server.
• Cascaded Revocation: A flood-based eviction routine
that reliably scrubs de-listed device certificates across all
mesh members.
• Working Reference Implementation: Complete integration into Link, our open-source multi-device suite spanning Windows (Electron, TypeScript, C#) and Android
(Capacitor, Java), along with empirical benchmarks on
convergence time and resource usage.

We assume an untrusted Local Area Network populated by
honest devices alongside malicious entities, modeled after the
standard Dolev-Yao network adversary [8]. In this environment, network location provides zero inherent authority [9].
An attacker A on the same broadcast domain can:
• Sniff, alter, replay, or inject arbitrary TCP and UDP
packets.
• Execute ARP spoofing, rogue mDNS advertisements, and
DNS redirection.
• Attempt on-path Man-in-the-Middle (MitM) attacks during initial TLS handshakes using rogue self-signed certificates.
Security Bounds: We assume standard cryptographic
primitives—SHA-256 collision resistance, asymmetric signature safety, and TLS 1.3 cipher suites [10]—are computationally secure. We also assume the adversary cannot access
physical device screens or intercept user inputs during the outof-band (OOB) visual verification step.
B. Core Security Invariants
T-TOFU enforces three operational security invariants:
• Guaranteed Mutual Authenticity: An outsider node
cannot join the mesh or establish authenticated TLS
sessions with any pool member without completing an
explicit OOB visual verification ceremony with at least
one active peer.
• Transitive Trust Propagation: An authorized gateway
node B in pool P that authenticates a new node A
automatically vouches for A to all other pool members
C ∈ P . Trust between C and A is established through
secure gossip without requiring additional human verification.
• Eventual Revocation Convergence: When an authorized
user triggers an unpair action targeting a device, the
revocation notice floods across all reachable mesh links
within O(diameter(P )) hops, purging the target’s pinned
certificate from every member’s trust store.

D. Gossip Synchronization and Transitive Ingestion
Peers maintain persistent TLS WebSockets carrying JSON
control messages. Every two seconds (Theartbeat = 2 s), each
device broadcasts its current PoolHash. If a peer stays silent
for five seconds, its link is marked offline.
When node A receives a heartbeat from trusted peer B
with a differing digest (PoolHashB ̸= PoolHashA ), it initiates
anti-entropy reconciliation: nodes reciprocally exchange their
active trust tables through link.pool.sync. When node
B encounters unfamiliar device records sent by A, it verifies
that A is an authentic peer, saves the received certificates, and
pins their fingerprints. Node B then recomputes its pool hash
and gossips the update to remaining peers.
E. Cascaded Eviction and Revocation
When a user removes device X from the mesh via device
A, node A removes X from its database and closes all active
sockets to X. It then floods an authenticated revocation frame
(link.pool.remove) across the network. Receiving peers
check their local stores; if the target is found, they delete
the certificate, update their PoolHash, and forward the packet
outward until the mesh converges.

C. Security Analysis
Resistance to MitM Interception: An attacker attempting to intercept the gateway pairing cannot forge the outof-band 8-character verification string displayed on the
physical screens. In addition, because nodes only accept
link.pool.sync packets over established, certificatepinned TLS connections, attackers cannot inject unauthorized certificates through spoofed broadcast frames.
• Network Partition Recovery: If a subnet split causes
nodes to pair independently on separate segments, reconnecting devices detect the divergence on the next
heartbeat via differing PoolHash values, prompting an
automatic reciprocal sync that unifies the trust tables.

VI. R ELATED W ORK
Decentralized Key Trust: Decentralized trust models
date back to Zimmermann’s PGP Web of Trust [13] and
SPKI/SDSI [14]. However, PGP required users to manually
configure trust depths and understand key validity, which
proved overly burdensome for typical users [15]. Stajano
and Anderson introduced the Resurrecting Duckling policy
for ad-hoc wireless peripherals [16], where devices imprint
permanently on a master node via physical touch. T-TOFU
adapts this philosophy for symmetric, multi-master personal
device meshes where no single machine serves as a permanent
master. Syncthing offers an “introducer” flag where one device
shares its known peer list [17]; T-TOFU makes all members
symmetrical introducers while adding digest-based consistency
checking and cascaded revocation.
Cross-Device Integration Tools: Existing cross-platform
integration suites include KDE Connect [5] and Apple AirDrop [18]. KDE Connect relies strictly on pairwise manual

VII. C ONCLUSION AND F UTURE W ORK
This paper introduced Transitive Trust-on-First-Use (TTOFU), a coordinator-free trust architecture that resolves the
Usable-Security Trilemma in personal device networks. By
unifying human-in-the-loop gateway pairing, canonical pool
digest gossip, and flooded certificate revocation, T-TOFU
eliminates the O(N 2 ) pairing bottleneck while preserving
strict local-first privacy and TLS 1.3 cryptographic integrity.
We verified T-TOFU across Windows and Android in the
open-source Link ecosystem, demonstrating sub-100ms mesh
convergence and low network overhead.
Future work includes formalizing the state machine in
automated protocol verifiers like ProVerif, as well as integrating threshold cryptography for shared multi-user home
environments.
