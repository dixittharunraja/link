2. CORE TECHNICAL NOVELTIES & ARCHITECTURAL CONTRIBUTIONS
--------------------------------------------------------------------------------

NOVELTY 1: Transitive Trust-on-First-Use (T-TOFU) with Hash Gossip & Cascaded Revocation
--------------------------------------------------------------------------------
* Problem: Current P2P architectures force users into an O(N^2) pairing matrix 
  (entering PINs / scanning QR codes between every single device pair) or require 
  centralized identity providers (Apple iCloud, Microsoft Account, Google Sign-in) 
  that introduce WAN latency, privacy risks, and single points of failure.
* Link's Novel Solution:
  - Transitive Trust Propagation: Device A pairs with Device B via a human-gated 
    PIN/QR exchange. If Device B is already a member of a Trusted Pool P = {B, C, D}, 
    B automatically sends an authenticated `link.pool.sync` containing the pinned 
    X.509 DER/PEM public certificates of all pool members.
  - A ingests {C, D} and automatically registers their certificate fingerprints 
    into its encrypted local trust store without requiring a second human PIN.
  - Canonical Pool Hash Synchronization:
      PoolHash = Substring(SHA-256( Sort( (DevID_i : Fingerprint_i) for all i in P ) ), 0, 16)
    On every periodic heartbeat, nodes exchange their 16-character PoolHash. If a hash 
    divergence is detected, an automatic pool synchronization exchange is triggered.
  - Decentralized Cascaded Revocation: When any authorized member issues an unpair 
    request (`link.pair: {pair: false}` or `link.pool.remove`), the revocation 
    packet gossips across all active mesh nodes, deterministically purging the 
    target certificate and restoring the removed device to a stranger state.

NOVELTY 2: Asymmetric 3-Plane Heterogeneous Transport Architecture
--------------------------------------------------------------------------------
* Problem: Traditional inter-device tools multiplex all events over a single TCP/TLS 
  socket (leading to Head-of-Line blocking, buffer bloat, and serialization drag) 
  or rely on complex, heavyweight WebRTC peer connection topologies.
* Link's Novel Solution:
  Link partitions all communication across three independent, purpose-built QoS planes:
  
  [Plane 1: Persistent Control Plane (TLS 1.3 / WSS)]
  - Low-overhead JSON-RPC for device state machines, notifications, telephony state, 
    and pool integrity heartbeats.
  
  [Plane 2: Ephemeral Out-of-Band Bulk Data Plane (Raw Binary TLS Sockets)]
  - Eliminates JSON/Base64 serialization overhead and protocol framing.
  - Senders launch a dynamic, one-shot TLS server on an ephemeral random port.
  - Receivers connect directly to the ephemeral port and pull raw byte streams using 
    a tuned 64KB-128KB chunked buffer loop with active drain-backpressure.
  - Results in 100% line-rate LAN saturation (~3x speed increase over standard 
    chunked HTTP/JSON transfers).
  
  [Plane 3: Stateless Real-Time HID Plane (UDP Datagrams on Port 1717)]
  - Sub-5ms latency transport dedicated to high-frequency telemetry (touchpad, 
    gamepad joystick inputs, presenter pointer, landscape-mapped digitizer pen events).
  - Eliminates TCP retransmission delays and buffer queuing for real-time human input.

NOVELTY 3: Real-Time Encrypted P2P Audio Relay & Virtual Microphone Synthesis
--------------------------------------------------------------------------------
* Problem: Operating systems isolate audio pipelines. Streaming system audio or 
  using a mobile phone as a zero-latency PC microphone typically requires proprietary 
  cables, specialized soundcards, or clunky third-party virtual audio loopback drivers.
* Link's Novel Solution:
  - System Audio Streaming: Host captures PCM system audio -> Encodes via low-latency 
    Opus codec -> Encrypts frames using authenticated AES-256-GCM -> Broadcasts over 
    UDP to authenticated listeners with real-time host-side kick/mute controls.
  - Virtual Microphone: Reverses the pipeline, capturing mobile audio via Android 
    AudioRecord APIs -> Opus stream -> injected on Windows as an active audio input 
    source accessible by communication apps (Zoom, Teams, Discord).

NOVELTY 4: User-Space Filesystem Virtualization over Encrypted WebSockets (VFS / WebDAV)
--------------------------------------------------------------------------------
* Problem: Accessing mobile files on desktop has historically relied on sluggish MTP 
  USB protocols, manual cloud uploads, or clunky SFTP browser windows.
* Link's Novel Solution:
  - Directly exposes remote Android storage as a native Windows drive letter (Z:) 
    within Windows Explorer.
  - Bridges a secure `wss://` TLS stream running on Android with a local in-process 
    HTTP WebDAV engine in Electron, mounted via WinFsp / network redirector mode.
  - Implements dynamic WebDAV RFC quota translation (`quota-available-bytes` / 
    `quota-used-bytes`) and write-back caching to guarantee OS shell stability 
    without kernel driver panics.

NOVELTY 5: Ephemeral "Portal" Protocol (Zero-Trust Ad-Hoc Guest Transfers)
--------------------------------------------------------------------------------
* Problem: Transferring files to untrusted guest devices usually requires permanent 
  pairing (polluting the trust store) or third-party cloud intermediaries.
* Link's Novel Solution:
  - Completely isolated one-time transfer protocol.
  - Both devices spin up an isolated TLS socket on a dedicated guest port.
  - A 4-digit human verification PIN is derived deterministically from the raw 
    TLS certificate public keys.
  - Once the file stream terminates, the guest session is completely dismantled with 
    zero state persisted to the long-term Trusted Pool.

NOVELTY 6: Precision Absolute Digitizer Mapping & Screen-Saver Overlay Injection
--------------------------------------------------------------------------------
* Problem: Touch-based input streaming suffers from coordinate snapping on finger lift 
  and window-order occlusion during full-screen slide presentations.
* Link's Novel Solution:
  - Absolute Landscape Digitizer Mapping: Transforms mobile touch coordinates with 
    pressure curves (0.0 to 1.0) into desktop screen space percentages, caching 
    the terminal position on `touchend` to prevent cursor snap-back to (0,0).
  - Elevated Presenter Engine: The desktop presenter laser pointer overlay window 
    is programmatically elevated to the `screen-saver` Z-order band, rendering cleanly 
    on top of exclusive full-screen PowerPoint and Google Slides instances.

3. MATHEMATICAL & ALGORITHMIC FORMALIZATION
--------------------------------------------------------------------------------

3.1 Pool Hash Invariant
-----------------------
Let P be the set of trusted devices {d_1, d_2, ..., d_n}.
Each device d_i has a unique identifier ID_i and an X.509 public key fingerprint FP_i.

The canonical pool representation is defined as:
  S(P) = Sort_lexicographical( { (ID_i, FP_i) | d_i in P } )
  CanonicalString(P) = Concat_with_delimiter( S(P), "|" )
  PoolHash(P) = Truncate_16( Hex( SHA-256( CanonicalString(P) ) ) )

Invariant 1 (Pool Consistency):
  For any two nodes A, B in pool P, A and B are in mutual synchronization if and 
  only if PoolHash_A(P) == PoolHash_B(P).

3.2 Transitive Trust State Transition Function
----------------------------------------------
Let T_A be the local trust store of Node A.
When Node A receives a pool synchronization packet from trusted peer B (where B in T_A):
  IncomingTrustList = { (ID_k, Cert_k, Name_k, IP_k) } from B
  For each device k in IncomingTrustList:
    If ID_k not in T_A:
      T_A = T_A U { (ID_k, Cert_k, Name_k, IP_k, PairedAt = Now()) }
      Broadcast(link.pool.sync, T_A)
